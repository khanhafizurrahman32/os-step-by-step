Why can two processes print the same address for a variable yet hold different values?<br><small>L01 · Intro &amp; the three pieces</small>	Each has its own virtual address space; the same virtual address maps to different physical memory.	ostep virtualization L01
Why does a shared counter incremented by two threads end up wrong?<br><small>L01 · Intro &amp; the three pieces</small>	<code>counter++</code> is load–add–store. How does a system call differ from a procedure call?<br><small>L01 · Intro &amp; the three pieces</small>	It traps into the kernel and raises the hardware privilege level, so the OS can perform restricted operations; a procedure call stays in user mode.	ostep virtualization L01
What does fork() return in the parent and in the child?<br><small>L02 · Processes &amp; fork / exec / wait</small>	Child's PID in the parent; 0 in the child; −1 on failure.	ostep virtualization L02
When does exec() return?<br><small>L02 · Processes &amp; fork / exec / wait</small>	Only if it fails. On success the calling program is replaced and the old code is gone.	ostep virtualization L02
Why does UNIX split process creation into fork() and exec()?<br><small>L02 · Processes &amp; fork / exec / wait</small>	So code can run in the child between the two, to set up redirection, pipes or other environment changes before the new program starts.	ostep virtualization L02
What are the three main process states and their transitions?<br><small>L02 · Processes &amp; fork / exec / wait</small>	Running, Ready, Blocked. Running→Ready (descheduled), Ready→Running (scheduled), Running→Blocked (I/O starts), Blocked→Ready (I/O done).	ostep virtualization L02
What is a zombie process?<br><small>L02 · Processes &amp; fork / exec / wait</small>	One that has exited but whose parent hasn't called wait() to collect its exit status.	ostep virtualization L02
What does the OS store in a process control block (PCB)?<br><small>L02 · Processes &amp; fork / exec / wait</small>	Saved registers (context), state, PID, parent, memory info, open files, and similar per-process data.	ostep virtualization L02
What does "limited direct execution" mean?<br><small>L03 · Limited direct execution</small>	Run the program directly on the CPU for speed, but limit it: user mode, traps for privileged operations, and a timer interrupt so the OS regains control.	ostep virtualization L03
What is the trap table and when is it set up?<br><small>L03 · Limited direct execution</small>	A table of handler addresses for traps/interrupts. The kernel installs it at boot using a privileged instruction.	ostep virtualization L03
Why does the cooperative approach fail?<br><small>L03 · Limited direct execution</small>	A process stuck in an infinite loop never makes a syscall, so the OS never runs again; you must reboot.	ostep virtualization L03
How does the OS regain control in the non-cooperative approach?<br><small>L03 · Limited direct execution</small>	A hardware timer interrupt every few milliseconds jumps into the OS's interrupt handler.	ostep virtualization L03
In a context switch, which registers does the hardware save and which does the OS save?<br><small>L03 · Limited direct execution</small>	Hardware saves the user registers onto the process's kernel stack on the interrupt. The OS saves the kernel registers into the process's PCB in switch().	ostep virtualization L03
Why pass a system-call number instead of an address?<br><small>L03 · Limited direct execution</small>	So user code can only reach approved kernel entry points; it can't jump into the middle of the kernel.	ostep virtualization L03
Define turnaround time and response time.<br><small>L04 · Scheduling basics: FIFO, SJF, STCF, RR</small>	Turnaround = completion − arrival. Response = first run − arrival.	ostep virtualization L04
What is the convoy effect?<br><small>L04 · Scheduling basics: FIFO, SJF, STCF, RR</small>	Short jobs stuck waiting behind a long job in FIFO, inflating average turnaround.	ostep virtualization L04
What's the difference between SJF and STCF?<br><small>L04 · Scheduling basics: FIFO, SJF, STCF, RR</small>	SJF is non-preemptive: it picks the shortest job when choosing. STCF preempts the running job whenever a new job has less remaining time.	ostep virtualization L04
Why does RR have poor turnaround?<br><small>L04 · Scheduling basics: FIFO, SJF, STCF, RR</small>	It stretches every job out across many slices, so all jobs finish near the end.	ostep virtualization L04
What's the trade-off in choosing RR's time slice?<br><small>L04 · Scheduling basics: FIFO, SJF, STCF, RR</small>	Shorter = better response but more context-switch overhead; longer amortizes the switch cost but hurts response.	ostep virtualization L04
How does the scheduler use I/O to improve utilisation?<br><small>L04 · Scheduling basics: FIFO, SJF, STCF, RR</small>	When a job blocks on I/O, run another job; treat each CPU burst as a separate job so interactive bursts run quickly and overlap with I/O.	ostep virtualization L04
What is MLFQ's key idea?<br><small>L05 · MLFQ, lottery &amp; multiprocessor scheduling</small>	Use several priority queues and adjust a job's priority based on its observed behaviour, so it approximates SJF without knowing job lengths.	ostep virtualization L05
Which MLFQ rule prevents starvation, and what else does it fix?<br><small>L05 · MLFQ, lottery &amp; multiprocessor scheduling</small>	Rule 5 (periodic priority boost). It also lets a job that became interactive get back to high priority.	ostep virtualization L05
How could a program game the original MLFQ, and what fixes it?<br><small>L05 · MLFQ, lottery &amp; multiprocessor scheduling</small>	Issue an I/O just before its slice ends to stay at high priority. Fixed by accounting for total time used at a level (new Rule 4).	ostep virtualization L05
Why do higher MLFQ queues get shorter time slices?<br><small>L05 · MLFQ, lottery &amp; multiprocessor scheduling</small>	They hold interactive jobs that need fast switching; lower queues hold CPU-bound jobs that benefit from long slices with less switching.	ostep virtualization L05
Lottery vs stride scheduling?<br><small>L05 · MLFQ, lottery &amp; multiprocessor scheduling</small>	Lottery picks a random ticket each slice — simple, no global state, fair on average. Stride is deterministic (run lowest pass, add stride) — exactly fair but needs global state.	ostep virtualization L05
How does Linux CFS pick the next process?<br><small>L05 · MLFQ, lottery &amp; multiprocessor scheduling</small>	The one with the lowest virtual runtime, stored in a red-black tree; nice values weight how fast vruntime grows.	ostep virtualization L05
Single-queue vs multi-queue multiprocessor scheduling?<br><small>L05 · MLFQ, lottery &amp; multiprocessor scheduling</small>	Single-queue: simple, balanced, but lock contention and poor cache affinity. Multi-queue: scalable and affinity-friendly, but needs migration/work stealing to fix load imbalance.	ostep virtualization L05
What are the three segments of a typical address space and how do they grow?<br><small>L06 · Address spaces &amp; the memory API</small>	Code (fixed), heap (grows towards higher addresses), stack (grows towards lower addresses).	ostep virtualization L06
What are the three goals of virtual memory?<br><small>L06 · Address spaces &amp; the memory API</small>	Transparency, efficiency (time and space), protection/isolation.	ostep virtualization L06
Is malloc() a system call?<br><small>L06 · Address spaces &amp; the memory API</small>	No. It's a library routine; it gets memory from the OS with brk/sbrk or mmap.	ostep virtualization L06
Why must you allocate strlen(s)+1 bytes to copy a string?<br><small>L06 · Address spaces &amp; the memory API</small>	To leave room for the terminating null byte.	ostep virtualization L06
What is a dangling pointer?<br><small>L06 · Address spaces &amp; the memory API</small>	A pointer to memory that has already been freed; using it is undefined behaviour.	ostep virtualization L06
How does base-and-bounds translation work?<br><small>L07 · Address translation: base/bounds &amp; segmentation</small>	Physical = virtual + base; if virtual ≥ bounds, the hardware raises an exception.	ostep virtualization L07
Where do base and bounds live, and who can change them?<br><small>L07 · Address translation: base/bounds &amp; segmentation</small>	In the CPU's MMU; only privileged (kernel-mode) instructions can change them. The OS saves/restores them in the PCB on a context switch.	ostep virtualization L07
What problem does segmentation solve over base-and-bounds?<br><small>L07 · Address translation: base/bounds &amp; segmentation</small>	It avoids wasting physical memory for the unused space between heap and stack, by relocating each segment separately.	ostep virtualization L07
How does the hardware know which segment a virtual address is in?<br><small>L07 · Address translation: base/bounds &amp; segmentation</small>	Typically the top bits of the virtual address select the segment; the rest is the offset.	ostep virtualization L07
What is external fragmentation and why does segmentation cause it?<br><small>L07 · Address translation: base/bounds &amp; segmentation</small>	Free memory split into many small variable-sized holes. Segments have different sizes, so allocating and freeing them leaves gaps too small to use.	ostep virtualization L07
How are code segments shared between processes?<br><small>L07 · Address translation: base/bounds &amp; segmentation</small>	With protection bits: a read-execute-only code segment can be mapped into many address spaces safely.	ostep virtualization L07
How does free() know the size of the block?<br><small>L08 · Free-space management</small>	It reads a header stored just before the returned pointer, which holds the size (and a magic number for integrity).	ostep virtualization L08
What is coalescing?<br><small>L08 · Free-space management</small>	Merging a freed chunk with adjacent free chunks into a single larger free chunk.	ostep virtualization L08
Best fit vs first fit?<br><small>L08 · Free-space management</small>	Best fit searches the whole list for the smallest hole that fits (less waste, slow, slivers). First fit takes the first hole that fits (fast, slivers at the list head).	ostep virtualization L08
How does the buddy allocator make coalescing easy?<br><small>L08 · Free-space management</small>	Blocks are powers of two; a block's buddy address differs by a single bit, so checking and merging is quick and recursive.	ostep virtualization L08
What's the main downside of the buddy allocator?<br><small>L08 · Free-space management</small>	Internal fragmentation, because requests are rounded up to a power of two.	ostep virtualization L08
What is a page vs a page frame?<br><small>L09 · Paging</small>	A page is a fixed-size chunk of virtual memory; a page frame is the same-size slot in physical memory.	ostep virtualization L09
How is a virtual address split under paging?<br><small>L09 · Paging</small>	High bits = virtual page number (VPN); low log2(page size) bits = offset.	ostep virtualization L09
Which part of the address does the page table translate?<br><small>L09 · Paging</small>	Only the VPN → PFN. The offset is copied unchanged.	ostep virtualization L09
How large is a linear page table for a 32-bit space with 4 KB pages and 4-byte PTEs?<br><small>L09 · Paging</small>	2^20 entries × 4 bytes = 4 MB per process.	ostep virtualization L09
Why is basic paging slow?<br><small>L09 · Paging</small>	Each memory reference needs an extra memory access to fetch the PTE first.	ostep virtualization L09
Valid bit vs present bit?<br><small>L09 · Paging</small>	Valid: the page belongs to the address space. Present: the page is currently in physical memory (not swapped out).	ostep virtualization L09
Two advantages of paging over segmentation?<br><small>L09 · Paging</small>	No external fragmentation (all frames same size), and flexible support for sparse address spaces.	ostep virtualization L09
What does the TLB store?<br><small>L10 · TLBs: making paging fast</small>	Recently used virtual-to-physical page translations (VPN → PFN plus protection and other bits).	ostep virtualization L10
Why does the TLB work well for most programs?<br><small>L10 · TLBs: making paging fast</small>	Spatial and temporal locality: nearby accesses fall in the same page and pages get reused.	ostep virtualization L10
Hardware-managed vs software-managed TLB miss?<br><small>L10 · TLBs: making paging fast</small>	Hardware: the CPU walks the page table itself (x86). Software: the CPU traps to the OS, which walks the table and installs the entry (MIPS) — more flexible.	ostep virtualization L10
What's special about returning from a TLB-miss trap?<br><small>L10 · TLBs: making paging fast</small>	It must retry the instruction that caused the miss, unlike a syscall return which continues with the next instruction.	ostep virtualization L10
How do ASIDs help with context switches?<br><small>L10 · TLBs: making paging fast</small>	Entries are tagged with the address-space ID, so the TLB can hold translations for several processes without flushing.	ostep virtualization L10
What is TLB coverage?<br><small>L10 · TLBs: making paging fast</small>	Number of entries × page size — the amount of memory reachable without a TLB miss.	ostep virtualization L10
Why are linear page tables wasteful?<br><small>L11 · Smaller page tables: multi-level &amp; friends</small>	They allocate a PTE for every virtual page, even the vast unused region between heap and stack.	ostep virtualization L11
How does a multi-level page table save space?<br><small>L11 · Smaller page tables: multi-level &amp; friends</small>	The page table is split into page-sized chunks; a page directory tracks them, and chunks with no valid entries are never allocated.	ostep virtualization L11
What's the cost of a two-level page table?<br><small>L11 · Smaller page tables: multi-level &amp; friends</small>	On a TLB miss, two memory accesses instead of one to translate (plus more complexity).	ostep virtualization L11
How many 4-byte PTEs fit in a 4 KB page, and what does that imply?<br><small>L11 · Smaller page tables: multi-level &amp; friends</small>	1024 → each level indexes with 10 bits.	ostep virtualization L11
What's an inverted page table?<br><small>L11 · Smaller page tables: multi-level &amp; friends</small>	A single system-wide table with one entry per physical frame, recording which process and virtual page use it; searched with a hash table.	ostep virtualization L11
Why not just use bigger pages?<br><small>L11 · Smaller page tables: multi-level &amp; friends</small>	Internal fragmentation: most of each big page goes unused for small allocations.	ostep virtualization L11
What is the present bit?<br><small>L12 · Swapping: going beyond physical memory</small>	A PTE bit saying whether the page is in physical memory (1) or swapped out to disk (0).	ostep virtualization L12
What happens on a page fault?<br><small>L12 · Swapping: going beyond physical memory</small>	The OS finds a free frame (evicting one if needed), reads the page from swap, sets present=1 and the PFN, and the faulting instruction is retried. The process is blocked during the I/O.	ostep virtualization L12
Write the average memory access time formula.<br><small>L12 · Swapping: going beyond physical memory</small>	AMAT = T_M + P_miss × T_D.	ostep virtualization L12
What does OPT evict and why can't we use it?<br><small>L12 · Swapping: going beyond physical memory</small>	The page that will be used furthest in the future; it requires knowing the future.	ostep virtualization L12
What is Belady's anomaly?<br><small>L12 · Swapping: going beyond physical memory</small>	With FIFO, increasing cache size can increase the number of misses. LRU and OPT (stack algorithms) don't have it.	ostep virtualization L12
How does the Clock algorithm work?<br><small>L12 · Swapping: going beyond physical memory</small>	Pages in a circle with a hardware-set use bit. The hand sweeps: use bit 1 → clear it and move on; use bit 0 → evict.	ostep virtualization L12
Which workload makes LRU and FIFO miss every time?<br><small>L12 · Swapping: going beyond physical memory</small>	Looping sequentially over one more page than the cache holds.	ostep virtualization L12
What is thrashing and how is it handled?<br><small>L12 · Swapping: going beyond physical memory</small>	Memory is oversubscribed so the system spends its time paging. Run fewer processes (admission control) or kill one (OOM killer).	ostep virtualization L12
What is copy-on-write?<br><small>L12 · Swapping: going beyond physical memory</small>	After fork, parent and child share pages read-only; a page is copied only when one of them writes to it.	ostep virtualization L12
What do threads in a process share, and what is private to each?<br><small>L13 · Threads &amp; race conditions</small>	Shared: code, heap, globals, open files (the address space). Private: registers, program counter, stack.	ostep concurrency L13
Why might counter++ give the wrong result with two threads?<br><small>L13 · Threads &amp; race conditions</small>	It's load, add, store; an interrupt between them lets the other thread read the old value, and one update is lost.	ostep concurrency L13
Define critical section, race condition and mutual exclusion.<br><small>L13 · Threads &amp; race conditions</small>	Critical section: code touching shared data. Race condition: result depends on timing. Mutual exclusion: only one thread in the critical section at a time.	ostep concurrency L13
Two reasons to use threads?<br><small>L13 · Threads &amp; race conditions</small>	Parallelism on multiple CPUs, and avoiding blocking the program on slow I/O.	ostep concurrency L13
Why is returning a pointer to a local variable from a thread a bug?<br><small>L13 · Threads &amp; race conditions</small>	The local lives on the thread's stack, which is freed when the thread exits.	ostep concurrency L13
Three criteria for evaluating a lock?<br><small>L14 · Locks</small>	Correctness (mutual exclusion), fairness (no starvation), performance (overhead uncontended, one CPU, many CPUs).	ostep concurrency L14
Why doesn't disabling interrupts work as a general lock?<br><small>L14 · Locks</small>	It's privileged (programs could abuse it), doesn't work on multiprocessors, can lose interrupts, and is slow on modern CPUs. OK only inside the kernel briefly.	ostep concurrency L14
Why does a simple flag-based lock fail?<br><small>L14 · Locks</small>	Testing the flag and setting it are separate steps; an interrupt in between lets two threads both see it free and both enter.	ostep concurrency L14
What does test-and-set do?<br><small>L14 · Locks</small>	Atomically returns the old value at an address and sets it to a new value.	ostep concurrency L14
How does a ticket lock guarantee fairness?<br><small>L14 · Locks</small>	Fetch-and-add hands out increasing tickets; the lock serves turns in order, so each thread gets in once its number comes up.	ostep concurrency L14
Why are spin locks bad on a single CPU?<br><small>L14 · Locks</small>	A waiting thread spins for its whole time slice, but the holder can't run to release the lock during that time.	ostep concurrency L14
What is the wakeup/waiting race and how is it fixed?<br><small>L14 · Locks</small>	A thread about to park() gets unparked before it sleeps, then sleeps forever. Solaris fixes it with setpark(); futexes check the value atomically in the kernel.	ostep concurrency L14
What is a two-phase lock?<br><small>L14 · Locks</small>	Spin for a short time hoping the lock frees up soon; if not, sleep until woken.	ostep concurrency L14
How does a sloppy (approximate) counter work?<br><small>L15 · Lock-based concurrent data structures</small>	Per-CPU local counters with their own locks; when one reaches threshold S it's added to the global counter. Low contention, but the global value lags.	ostep concurrency L15
What's the effect of increasing S in a sloppy counter?<br><small>L15 · Lock-based concurrent data structures</small>	Better scalability, less accurate global count.	ostep concurrency L15
Why does the Michael &amp; Scott queue use a dummy node?<br><small>L15 · Lock-based concurrent data structures</small>	To keep the head and tail operations on separate nodes so the head lock and tail lock can be held concurrently.	ostep concurrency L15
Why does a hash table with per-bucket locks scale well?<br><small>L15 · Lock-based concurrent data structures</small>	Operations on different buckets don't contend for the same lock.	ostep concurrency L15
What's hand-over-hand locking and why is it often slow?<br><small>L15 · Lock-based concurrent data structures</small>	A lock per node; you grab the next node's lock before releasing the current one. The per-node lock overhead usually outweighs the extra concurrency.	ostep concurrency L15
What does pthread_cond_wait(c, m) do?<br><small>L16 · Condition variables</small>	Atomically releases mutex m and puts the thread to sleep on c; when woken, re-acquires m before returning.	ostep concurrency L16
Why must you re-check the condition in a while loop?<br><small>L16 · Condition variables</small>	Mesa semantics: the signal is only a hint and the state may change before the woken thread runs; spurious wakeups can also happen.	ostep concurrency L16
Why do we need a state variable along with a CV?<br><small>L16 · Condition variables</small>	CVs have no memory. If signal happens before wait, it's lost; the state variable records that the condition already holds.	ostep concurrency L16
Why does producer/consumer need two condition variables?<br><small>L16 · Condition variables</small>	So a consumer only wakes producers and a producer only wakes consumers; with one CV a consumer can wake another consumer and everyone sleeps.	ostep concurrency L16
What is a covering condition?<br><small>L16 · Condition variables</small>	Using broadcast to wake all waiters when you can't tell which one should proceed; each re-checks its condition.	ostep concurrency L16
Mesa vs Hoare semantics?<br><small>L16 · Condition variables</small>	Mesa: signal is a hint; the woken thread runs later and must re-check. Hoare: the woken thread runs immediately with the guarantee. Real systems use Mesa.	ostep concurrency L16
What do sem_wait and sem_post do?<br><small>L17 · Semaphores</small>	sem_wait decrements and sleeps if the value is negative; sem_post increments and wakes one waiter if any. Both are atomic.	ostep concurrency L17
What does a negative semaphore value mean?<br><small>L17 · Semaphores</small>	Its magnitude is the number of threads waiting.	ostep concurrency L17
What initial value makes a semaphore a lock? For ordering?<br><small>L17 · Semaphores</small>	1 for a lock (binary semaphore); 0 for ordering (wait until another thread posts).	ostep concurrency L17
Why must the mutex be acquired inside wait(empty)/wait(full) in producer/consumer?<br><small>L17 · Semaphores</small>	Otherwise a thread can sleep on full/empty while holding the mutex, so the other side can never get the mutex to post — deadlock.	ostep concurrency L17
How does a reader-writer lock work and what's its weakness?<br><small>L17 · Semaphores</small>	The first reader takes the write lock, the last reader releases it; writers need the write lock. Readers can starve writers.	ostep concurrency L17
How do you avoid deadlock in dining philosophers?<br><small>L17 · Semaphores</small>	Make one philosopher acquire forks in the opposite order, breaking the circular wait.	ostep concurrency L17
Key difference between a semaphore and a condition variable?<br><small>L17 · Semaphores</small>	A semaphore has state (its count), so a post before a wait isn't lost; a CV signal with no waiter is lost.	ostep concurrency L17
What are the two main kinds of non-deadlock concurrency bugs?<br><small>L18 · Concurrency bugs, deadlock &amp; event-based concurrency</small>	Atomicity violations (a sequence assumed atomic isn't) and order violations (an assumed ordering isn't enforced).	ostep concurrency L18
List the four conditions for deadlock.<br><small>L18 · Concurrency bugs, deadlock &amp; event-based concurrency</small>	Mutual exclusion, hold-and-wait, no preemption, circular wait.	ostep concurrency L18
What is the most practical way to prevent deadlock?<br><small>L18 · Concurrency bugs, deadlock &amp; event-based concurrency</small>	Break circular wait by acquiring locks in a fixed global order (e.g. by address).	ostep concurrency L18
What's livelock and how do you reduce it?<br><small>L18 · Concurrency bugs, deadlock &amp; event-based concurrency</small>	Threads keep failing trylock, releasing and retrying without progress. Add a random delay before retrying.	ostep concurrency L18
Prevention vs avoidance vs detection?<br><small>L18 · Concurrency bugs, deadlock &amp; event-based concurrency</small>	Prevention: design so a deadlock condition can't hold. Why must event handlers never block?<br><small>L18 · Concurrency bugs, deadlock &amp; event-based concurrency</small>	There's one thread; a blocking call stops the whole server from handling any other event.	ostep concurrency L18
What's a continuation in event-based programming?<br><small>L18 · Concurrency bugs, deadlock &amp; event-based concurrency</small>	Saved state needed to finish handling an event later, e.g. after async I/O completes.	ostep concurrency L18
What are the three registers of the canonical device interface?<br><small>L19 · I/O devices</small>	Status, command, data.	ostep persistence L19
When is polling better than interrupts?<br><small>L19 · I/O devices</small>	When the device is fast, so the first poll usually finds it done; interrupt handling and context switching would cost more.	ostep persistence L19
What is interrupt livelock?<br><small>L19 · I/O devices</small>	A flood of interrupts (e.g. network packets) keeps the CPU busy handling interrupts so no real work gets done.	ostep persistence L19
What does DMA do?<br><small>L19 · I/O devices</small>	A DMA engine transfers data between memory and a device without the CPU copying it, then raises an interrupt when finished.	ostep persistence L19

Why are device drivers a reliability problem?<br><small>L19 · I/O devices</small>	They make up most of the kernel's code (~70% of Linux), are often written by less experienced developers, and run in kernel mode.	ostep persistence L19

Why do SSDs need a flash translation layer?<br><small>L20 · Hard disks (and SSDs in brief)</small>	Flash must erase whole blocks before reprogramming pages and blocks wear out, so the FTL remaps writes log-style to fresh pages, garbage-collects and wear-levels.	ostep persistence L20
What does RAID-0 provide and not provide?<br><small>L21 · RAID</small>	Striping for full capacity and performance; no redundancy (any failure loses data).	ostep persistence L21
How does parity let RAID-4/5 recover a failed disk?<br><small>L21 · RAID</small>	Parity is the XOR of the stripe's data blocks; XOR-ing the surviving blocks and parity reconstructs the missing one.	ostep persistence L21
