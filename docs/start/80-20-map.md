# The 80/20 map

Every chapter of OSTEP, sorted into three tiers.

- 🔴 **Must** — read the chapter's marked sections, do the recall, do the homework simulator if there is one. These carry ~80% of exam and interview questions.
- 🟡 **Skim** — read the lesson here, look at the figures in the book, skip the prose.
- ⚪ **Skip** — dialogues, history, deep case studies. Come back only if you're curious.

**Total for 🔴 + 🟡: about 35–40 hours** instead of ~120 for the whole book.

## Why this split works

Three ideas show up again and again across the whole book. If you understand them, the 🟡 chapters mostly become "the same idea, applied again":

1. **Mechanism vs. policy.** *How* something is done (context switch, page table walk) is separate from *which* choice is made (which process runs, which page is evicted). Every Part I chapter is one or the other.
2. **Add a level of indirection, then cache it.** Virtual → physical addresses, then the TLB. File name → inode → blocks, then the buffer cache. Inode map in LFS.
3. **Make the common case fast, and handle the rare case correctly.** Direct execution with traps, TLB hits vs. misses, journaling that only writes metadata twice.
