    Import into Anki (2 minutes)¶

    1. Download os-step-by-step-anki.txt (or take it from the flashcards/ folder of the repo).
    2. In Anki: File → Import, pick the file. The deck name, tab separator, HTML and tags are set by the file's header lines, so the defaults are right.
    3. Study daily. Anki's spacing replaces the +1/+3/+7/+21-day schedule in the recall system.

    Tags let you study one part or lesson: in the browser search for tag:concurrency or tag:L14. Unsuspend only the lessons you've done, so you're never quizzed on material you haven't read.

    Virtualization¶

    L01 · Intro & the three pieces

    Question Answer
    What are the "three easy pieces"? Virtualization, concurrency, persistence.
    Why can two processes print the same address for a variable yet hold different values? Each has its own virtual address space; the same virtual address maps to different physical memory.
    Why does a shared counter incremented by two threads end up wrong? counter++ is load–add–store. If a context switch hits between them, one thread's update overwrites the other's. The three instructions are not atomic.
    How does a system call differ from a procedure call? It traps into the kernel and raises the hardware privilege level, so the OS can perform restricted operations; a procedure call stays in user mode.

    L02 · Processes & fork / exec / wait

    Question Answer
    What does fork() return in the parent and in the child? Child's PID in the parent; 0 in the child; −1 on failure.
    When does exec() return? Only if it fails. On success the calling program is replaced and the old code is gone.
    Why does UNIX split process creation into fork() and exec()? So code can run in the child between the two, to set up redirection, pipes or other environment changes before the new program starts.
    What are the three main process states and their transitions? Running, Ready, Blocked. Running→Ready (descheduled), Ready→Running (scheduled), Running→Blocked (I/O starts), Blocked→Ready (I/O done).
    What is a zombie process? One that has exited but whose parent hasn't called wait() to collect its exit status.
    What does the OS store in a process control block (PCB)? Saved registers (context), state, PID, parent, memory info, open files, and similar per-process data.

    L03 · Limited direct execution

    Question Answer
    What does "limited direct execution" mean? Run the program directly on the CPU for speed, but limit it: user mode, traps for privileged operations, and a timer interrupt so the OS regains control.
    What is the trap table and when is it set up? A table of handler addresses for traps/interrupts. The kernel installs it at boot using a privileged instruction.
    Why does the cooperative approach fail? A process stuck in an infinite loop never makes a syscall, so the OS never runs again; you must reboot.
    How does the OS regain control in the non-cooperative approach? A hardware timer interrupt every few milliseconds jumps into the OS's interrupt handler.
    In a context switch, which registers does the hardware save and which does the OS save? Hardware saves the user registers onto the process's kernel stack on the interrupt. The OS saves the kernel registers into the process's PCB in switch().
    Why pass a system-call number instead of an address? So user code can only reach approved kernel entry points; it can't jump into the middle of the kernel.

    L04 · Scheduling basics: FIFO, SJF, STCF, RR

    Question Answer
    Define turnaround time and response time. Turnaround = completion − arrival. Response = first run − arrival.
    What is the convoy effect? Short jobs stuck waiting behind a long job in FIFO, inflating average turnaround.
    What's the difference between SJF and STCF? SJF is non-preemptive: it picks the shortest job when choosing. STCF preempts the running job whenever a new job has less remaining time.
    Why does RR have poor turnaround? It stretches every job out across many slices, so all jobs finish near the end.
    What's the trade-off in choosing RR's time slice? Shorter = better response but more context-switch overhead; longer amortizes the switch cost but hurts response.
    How does the scheduler use I/O to improve utilisation? When a job blocks on I/O, run another job; treat each CPU burst as a separate job so interactive bursts run quickly and overlap with I/O.

    L05 · MLFQ, lottery & multiprocessor scheduling

    Question Answer
    What is MLFQ's key idea? Use several priority queues and adjust a job's priority based on its observed behaviour, so it approximates SJF without knowing job lengths.
    Which MLFQ rule prevents starvation, and what else does it fix? Rule 5 (periodic priority boost). It also lets a job that became interactive get back to high priority.
    How could a program game the original MLFQ, and what fixes it? Issue an I/O just before its slice ends to stay at high priority. Fixed by accounting for total time used at a level (new Rule 4).
    Why do higher MLFQ queues get shorter time slices? They hold interactive jobs that need fast switching; lower queues hold CPU-bound jobs that benefit from long slices with less switching.
    Lottery vs stride scheduling? Lottery picks a random ticket each slice — simple, no global state, fair on average. Stride is deterministic (run lowest pass, add stride) — exactly fair but needs global state.
    How does Linux CFS pick the next process? The one with the lowest virtual runtime, stored in a red-black tree; nice values weight how fast vruntime grows.
    Single-queue vs multi-queue multiprocessor scheduling? Single-queue: simple, balanced, but lock contention and poor cache affinity. Multi-queue: scalable and affinity-friendly, but needs migration/work stealing to fix load imbalance.

    L06 · Address spaces & the memory API

    Question Answer
    What are the three segments of a typical address space and how do they grow? Code (fixed), heap (grows towards higher addresses), stack (grows towards lower addresses).
    What are the three goals of virtual memory? Transparency, efficiency (time and space), protection/isolation.
    Is malloc() a system call? No. It's a library routine; it gets memory from the OS with brk/sbrk or mmap.
    Why must you allocate strlen(s)+1 bytes to copy a string? To leave room for the terminating null byte.
    What is a dangling pointer? A pointer to memory that has already been freed; using it is undefined behaviour.

    L07 · Address translation: base/bounds & segmentation

    Question Answer
    How does base-and-bounds translation work? Physical = virtual + base; if virtual ≥ bounds, the hardware raises an exception.
    Where do base and bounds live, and who can change them? In the CPU's MMU; only privileged (kernel-mode) instructions can change them. The OS saves/restores them in the PCB on a context switch.
    What problem does segmentation solve over base-and-bounds? It avoids wasting physical memory for the unused space between heap and stack, by relocating each segment separately.
    How does the hardware know which segment a virtual address is in? Typically the top bits of the virtual address select the segment; the rest is the offset.
    What is external fragmentation and why does segmentation cause it? Free memory split into many small variable-sized holes. Segments have different sizes, so allocating and freeing them leaves gaps too small to use.
    How are code segments shared between processes? With protection bits: a read-execute-only code segment can be mapped into many address spaces safely.

    L08 · Free-space management

    Question Answer
    How does free() know the size of the block? It reads a header stored just before the returned pointer, which holds the size (and a magic number for integrity).
    What is coalescing? Merging a freed chunk with adjacent free chunks into a single larger free chunk.
    Best fit vs first fit? Best fit searches the whole list for the smallest hole that fits (less waste, slow, slivers). First fit takes the first hole that fits (fast, slivers at the list head).
    How does the buddy allocator make coalescing easy? Blocks are powers of two; a block's buddy address differs by a single bit, so checking and merging is quick and recursive.
    What's the main downside of the buddy allocator? Internal fragmentation, because requests are rounded up to a power of two.

    L09 · Paging

    Question Answer
    What is a page vs a page frame? A page is a fixed-size chunk of virtual memory; a page frame is the same-size slot in physical memory.
    How is a virtual address split under paging? High bits = virtual page number (VPN); low log2(page size) bits = offset.
    Which part of the address does the page table translate? Only the VPN → PFN. The offset is copied unchanged.
    How large is a linear page table for a 32-bit space with 4 KB pages and 4-byte PTEs? 2^20 entries × 4 bytes = 4 MB per process.
    Why is basic paging slow? Each memory reference needs an extra memory access to fetch the PTE first.
    Valid bit vs present bit? Valid: the page belongs to the address space. Present: the page is currently in physical memory (not swapped out).
    Two advantages of paging over segmentation? No external fragmentation (all frames same size), and flexible support for sparse address spaces.

    L10 · TLBs: making paging fast

    Question Answer
    What does the TLB store? Recently used virtual-to-physical page translations (VPN → PFN plus protection and other bits).
    Why does the TLB work well for most programs? Spatial and temporal locality: nearby accesses fall in the same page and pages get reused.
    Hardware-managed vs software-managed TLB miss? Hardware: the CPU walks the page table itself (x86). Software: the CPU traps to the OS, which walks the table and installs the entry (MIPS) — more flexible.
    What's special about returning from a TLB-miss trap? It must retry the instruction that caused the miss, unlike a syscall return which continues with the next instruction.
    How do ASIDs help with context switches? Entries are tagged with the address-space ID, so the TLB can hold translations for several processes without flushing.
    What is TLB coverage? Number of entries × page size — the amount of memory reachable without a TLB miss.

    L11 · Smaller page tables: multi-level & friends

    Question Answer
    Why are linear page tables wasteful? They allocate a PTE for every virtual page, even the vast unused region between heap and stack.
    How does a multi-level page table save space? The page table is split into page-sized chunks; a page directory tracks them, and chunks with no valid entries are never allocated.
    What's the cost of a two-level page table? On a TLB miss, two memory accesses instead of one to translate (plus more complexity).
    How many 4-byte PTEs fit in a 4 KB page, and what does that imply? 1024 → each level indexes with 10 bits.
    What's an inverted page table? A single system-wide table with one entry per physical frame, recording which process and virtual page use it; searched with a hash table.
    Why not just use bigger pages? Internal fragmentation: most of each big page goes unused for small allocations.

    L12 · Swapping: going beyond physical memory

    Question Answer
    What is the present bit? A PTE bit saying whether the page is in physical memory (1) or swapped out to disk (0).
    What happens on a page fault? The OS finds a free frame (evicting one if needed), reads the page from swap, sets present=1 and the PFN, and the faulting instruction is retried. The process is blocked during the I/O.
    Write the average memory access time formula. AMAT = T_M + P_miss × T_D.
    What does OPT evict and why can't we use it? The page that will be used furthest in the future; it requires knowing the future.
    What is Belady's anomaly? With FIFO, increasing cache size can increase the number of misses. LRU and OPT (stack algorithms) don't have it.
    How does the Clock algorithm work? Pages in a circle with a hardware-set use bit. The hand sweeps: use bit 1 → clear it and move on; use bit 0 → evict.
    Which workload makes LRU and FIFO miss every time? Looping sequentially over one more page than the cache holds.
    What is thrashing and how is it handled? Memory is oversubscribed so the system spends its time paging. Run fewer processes (admission control) or kill one (OOM killer).
    What is copy-on-write? After fork, parent and child share pages read-only; a page is copied only when one of them writes to it.

    Concurrency¶

    L13 · Threads & race conditions

    Question Answer
    What do threads in a process share, and what is private to each? Shared: code, heap, globals, open files (the address space). Private: registers, program counter, stack.
    Why might counter++ give the wrong result with two threads? It's load, add, store; an interrupt between them lets the other thread read the old value, and one update is lost.
    Define critical section, race condition and mutual exclusion. Critical section: code touching shared data. Race condition: result depends on timing. Mutual exclusion: only one thread in the critical section at a time.
    Two reasons to use threads? Parallelism on multiple CPUs, and avoiding blocking the program on slow I/O.
    Why is returning a pointer to a local variable from a thread a bug? The local lives on the thread's stack, which is freed when the thread exits.

    L14 · Locks

    Question Answer
    Three criteria for evaluating a lock? Correctness (mutual exclusion), fairness (no starvation), performance (overhead uncontended, one CPU, many CPUs).
    Why doesn't disabling interrupts work as a general lock? It's privileged (programs could abuse it), doesn't work on multiprocessors, can lose interrupts, and is slow on modern CPUs. OK only inside the kernel briefly.
    Why does a simple flag-based lock fail? Testing the flag and setting it are separate steps; an interrupt in between lets two threads both see it free and both enter.
    What does test-and-set do? Atomically returns the old value at an address and sets it to a new value.
    How does a ticket lock guarantee fairness? Fetch-and-add hands out increasing tickets; the lock serves turns in order, so each thread gets in once its number comes up.
    Why are spin locks bad on a single CPU? A waiting thread spins for its whole time slice, but the holder can't run to release the lock during that time.
    What is the wakeup/waiting race and how is it fixed? A thread about to park() gets unparked before it sleeps, then sleeps forever. Solaris fixes it with setpark(); futexes check the value atomically in the kernel.
    What is a two-phase lock? Spin for a short time hoping the lock frees up soon; if not, sleep until woken.

    L15 · Lock-based concurrent data structures

    Question Answer
    How does a sloppy (approximate) counter work? Per-CPU local counters with their own locks; when one reaches threshold S it's added to the global counter. Low contention, but the global value lags.
    What's the effect of increasing S in a sloppy counter? Better scalability, less accurate global count.
    Why does the Michael & Scott queue use a dummy node? To keep the head and tail operations on separate nodes so the head lock and tail lock can be held concurrently.
    Why does a hash table with per-bucket locks scale well? Operations on different buckets don't contend for the same lock.
    What's hand-over-hand locking and why is it often slow? A lock per node; you grab the next node's lock before releasing the current one. The per-node lock overhead usually outweighs the extra concurrency.

    L16 · Condition variables

    Question Answer
    What does pthread_cond_wait(c, m) do? Atomically releases mutex m and puts the thread to sleep on c; when woken, re-acquires m before returning.
    Why must you re-check the condition in a while loop? Mesa semantics: the signal is only a hint and the state may change before the woken thread runs; spurious wakeups can also happen.
    Why do we need a state variable along with a CV? CVs have no memory. If signal happens before wait, it's lost; the state variable records that the condition already holds.
    Why does producer/consumer need two condition variables? So a consumer only wakes producers and a producer only wakes consumers; with one CV a consumer can wake another consumer and everyone sleeps.
    What is a covering condition? Using broadcast to wake all waiters when you can't tell which one should proceed; each re-checks its condition.
    Mesa vs Hoare semantics? Mesa: signal is a hint; the woken thread runs later and must re-check. Hoare: the woken thread runs immediately with the guarantee. Real systems use Mesa.

    L17 · Semaphores

    Question Answer
    What do sem_wait and sem_post do? sem_wait decrements and sleeps if the value is negative; sem_post increments and wakes one waiter if any. Both are atomic.
    What does a negative semaphore value mean? Its magnitude is the number of threads waiting.
    What initial value makes a semaphore a lock? For ordering? 1 for a lock (binary semaphore); 0 for ordering (wait until another thread posts).
    Why must the mutex be acquired inside wait(empty)/wait(full) in producer/consumer? Otherwise a thread can sleep on full/empty while holding the mutex, so the other side can never get the mutex to post — deadlock.
    How does a reader-writer lock work and what's its weakness? The first reader takes the write lock, the last reader releases it; writers need the write lock. Readers can starve writers.
    How do you avoid deadlock in dining philosophers? Make one philosopher acquire forks in the opposite order, breaking the circular wait.
    Key difference between a semaphore and a condition variable? A semaphore has state (its count), so a post before a wait isn't lost; a CV signal with no waiter is lost.

    L18 · Concurrency bugs, deadlock & event-based concurrency

    Question Answer
    What are the two main kinds of non-deadlock concurrency bugs? Atomicity violations (a sequence assumed atomic isn't) and order violations (an assumed ordering isn't enforced).
    List the four conditions for deadlock. Mutual exclusion, hold-and-wait, no preemption, circular wait.
    What is the most practical way to prevent deadlock? Break circular wait by acquiring locks in a fixed global order (e.g. by address).
    What's livelock and how do you reduce it? Threads keep failing trylock, releasing and retrying without progress. Add a random delay before retrying.
    Prevention vs avoidance vs detection? Prevention: design so a deadlock condition can't hold. Avoidance: schedule so deadlock can't happen given known lock needs. Detection: let it happen, find cycles, recover.
    Why must event handlers never block? There's one thread; a blocking call stops the whole server from handling any other event.
    What's a continuation in event-based programming? Saved state needed to finish handling an event later, e.g. after async I/O completes.

    Persistence¶

    L19 · I/O devices

    Question Answer
    What are the three registers of the canonical device interface? Status, command, data.
    When is polling better than interrupts? When the device is fast, so the first poll usually finds it done; interrupt handling and context switching would cost more.
    What is interrupt livelock? A flood of interrupts (e.g. network packets) keeps the CPU busy handling interrupts so no real work gets done.
    What does DMA do? A DMA engine transfers data between memory and a device without the CPU copying it, then raises an interrupt when finished.
    Two ways the OS can access device registers? Privileged I/O instructions (in/out) or memory-mapped I/O.
    Why are device drivers a reliability problem? They make up most of the kernel's code (~70% of Linux), are often written by less experienced developers, and run in kernel mode.

    L20 · Hard disks (and SSDs in brief)

    Question Answer
    What's the disk I/O time formula? T_I/O = T_seek + T_rotation + T_transfer.
    Average rotational delay at 15,000 RPM? One rotation = 4 ms, so average = 2 ms (half a rotation).
    Roughly how much faster is sequential than random I/O on a hard disk? About 200–300×, e.g. 125 MB/s vs 0.66 MB/s.
    What's the problem with SSTF? Starvation of requests on far tracks; it also ignores rotational delay.
    What does SPTF do differently, and where is it implemented? Picks the request with the least seek + rotation time; implemented inside the drive, which knows the head position and geometry.
    What write is guaranteed atomic on a disk? A single 512-byte sector write.
    Why do SSDs need a flash translation layer? Flash must erase whole blocks before reprogramming pages and blocks wear out, so the FTL remaps writes log-style to fresh pages, garbage-collects and wear-levels.

    L21 · RAID

    Question Answer
    What does RAID-0 provide and not provide? Striping for full capacity and performance; no redundancy (any failure loses data).
    How does parity let RAID-4/5 recover a failed disk? Parity is the XOR of the stripe's data blocks; XOR-ing the surviving blocks and parity reconstructs the missing one.
    How many I/Os does a small write need in RAID-4/5, and why? Four: read old data and old parity, write new data and new parity (subtractive parity).
    Why is RAID-4 slow for small random writes? Every write must update the single parity disk, which serializes all writes (total R/2).
    How does RAID-5 fix RAID-4's problem? It rotates parity across all disks, so small writes to different stripes can proceed in parallel (N/4·R).
    Why is RAID-1's sequential read only N/2·S? Each disk serves every other block; it rotates past blocks its mirror is serving, so it delivers only half its bandwidth.
    Capacity of RAID-1, RAID-4, RAID-5 with N disks of B blocks? RAID-1: N·B/2. RAID-4 and RAID-5: (N−1)·B.

    L22 · Files & directories (the API)

    Question Answer
    What is an inode number? The file's low-level name; the file system uses it to find the inode (metadata and block pointers).
    What does a directory contain? A list of (name, inode number) pairs, including "." and "..".
    When do two file descriptors share an offset? When they refer to the same open-file-table entry: after fork() or dup(). Separate open() calls get separate offsets.
    Why call fsync()? write() buffers data in memory; fsync forces it (and metadata) to persistent storage.
    How do you update a file atomically? Write a temporary file, fsync it, then rename() it over the original; rename is atomic.
    Hard link vs symbolic link? Hard link: another name for the same inode (refcount). Symlink: a file containing a path; can cross file systems and point to directories, but can dangle.
    Why is the call to remove a file named unlink()? It removes one name (link) to the inode; the file is freed only when the link count drops to zero.

    L23 · File system implementation (VSFS)

    Question Answer
    Name the five regions of VSFS's on-disk layout. Superblock, inode bitmap, data bitmap, inode table, data region.
    What's in an inode? Metadata (type, size, owner, permissions, times, link count, block count) and pointers to data blocks.
    Max file size with 12 direct pointers, one indirect block, 4 KB blocks, 4-byte pointers? (12 + 1024) × 4 KB = 4144 KB ≈ 4 MB.
    Why does a multi-level (imbalanced) tree make sense for inodes? Most files are small and fit in direct pointers; the rare large files use indirect blocks.
    How many reads to open /foo/bar (no cache)? Five: root inode, root data, foo inode, foo data, bar inode.
    Why does reading a file cause a write? The inode's last-access time must be updated.
    Three benefits of write buffering? Batching updates into fewer I/Os, better scheduling of writes, and avoiding writes entirely for short-lived files.
    Extents vs pointers? An extent is a start pointer plus a length, describing a contiguous run with little metadata; pointers name each block but are more flexible.

    L24 · FFS: locality and the Fast File System

    Question Answer
    Why was the original UNIX file system so slow? It ignored disk geometry: inodes far from data (long seeks), a fragmented free list, and tiny 512-byte blocks.
    What is a cylinder (block) group? A contiguous region of the disk with its own copy of the superblock, inode and data bitmaps, inodes and data blocks.
    Where does FFS place a new file and a new directory? File: same group as its parent directory, with its data near its inode. Directory: a group with few directories and many free inodes.
    Why does FFS spread large files across groups? So one big file doesn't fill a group and destroy locality for other related files; chunks are large enough to amortise the seeks.
    What are sub-blocks for? 512-byte allocations for small files to avoid internal fragmentation with 4 KB blocks.

    L25 · Crash consistency: fsck & journaling

    Question Answer
    Which three blocks must be written to append one data block? The inode, the data bitmap, and the data block.
    What's the main drawback of fsck? It scans the entire disk, so recovery takes time proportional to disk size — far too slow for large disks.
    List the steps of data journaling. Journal write (TxB + contents), journal commit (TxE), checkpoint (write in place), free the journal space.
    Why must TxE be written separately, after the rest? The disk can reorder writes; if TxE lands first and the crash hits, recovery could replay garbage. TxE fits in one sector, so its write is atomic.
    What does recovery do with the journal? Replays (redoes) every committed transaction — those with a TxE — and ignores incomplete ones.
    In ordered metadata journaling, when is user data written? To its final location before the journal commit, so metadata never points to garbage.
    What rule underlies crash-consistent write ordering? Write the pointed-to object before the object that points to it.
    Why do metadata journaling instead of data journaling? Data journaling writes all data twice, halving write bandwidth; metadata is small.

    L26 · Log-structured file systems & data integrity

    Question Answer
    What's the core idea of LFS? Buffer all updates (data and metadata) in memory and write them sequentially as large segments to free space; never overwrite in place.
    Why does LFS need an inode map? Inodes move every time they're written, so the imap records each inode's current location.
    How does LFS find the imap? Through the checkpoint region, a fixed location that points to the latest imap pieces; it's updated periodically.
    How does the LFS cleaner decide if a block is live? The segment summary block gives the block's inode number and offset; if that inode (via the imap) still points to this address, it's live.
    What is a latent sector error vs silent corruption? LSE: the disk detects the bad sector and returns an error. Silent corruption: the disk returns wrong data with no error.
    How do you detect misdirected writes? Store the disk and sector address alongside the checksum and verify it on read.
    What is disk scrubbing? Periodically reading all blocks and verifying checksums to find corruption early.

    Distribution¶

    L27 · Distributed systems, NFS & AFS

    Question Answer
    How do you build reliable communication over an unreliable network? Acknowledgements, timeouts with retries, and sequence numbers to detect duplicates (plus checksums for corruption).
    What does an RPC stub do? Marshals arguments into a message, sends it, waits for the reply and unmarshals the result, so a remote call looks like a local one.
    Why is NFSv2 stateless, and what does that buy? Every request carries all needed information, so after a server crash clients simply retry — no state to rebuild.
    What's in an NFS file handle? Volume ID, inode number, generation number.
    What does idempotent mean, and why does NFS need it? Performing an operation more than once has the same effect as once; it makes retrying after timeouts safe.
    What are the two cache-consistency problems? Update visibility (when do others see my writes) and stale cache (is my cached copy out of date).
    What is an AFS callback? A promise from the server to notify a client when a file it caches is modified, so the client needn't ask the server on each open.
    Why must an NFS server commit writes to disk before replying? If it replied first and crashed, the client would think the data was safe when it was lost.
